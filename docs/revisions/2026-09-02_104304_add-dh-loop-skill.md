- **Date**: 2026-09-02 10:43:04

## Rationale / Plan

기존 `dh-dev` 스킬은 계획→검토→실행→커밋을 한 번 돌리고 끝난다. 실행 결과가 목표에 못 미쳐도 스스로 계획 단계로 되돌아가지 못하고, 매 계획마다 사용자 승인을 요구해 무인 반복이 불가능했다.

사용자 요구는 "dh-dev의 순서를 모두 구현하되, 검토에서 목표 값을 충족하지 못하면 계획 단계로 되돌아가 다시 실행·검토를 반복하고, 초기 계획 수립 이외에는 별도 승인 없이 진행"하는 것이다.

계획 문서: `docs/plans/2026-09-02_101002_add-dh-loop-skill.md`

핵심 설계 결정 다섯 가지.

| 결정 | 내용 | 근거 |
| --- | --- | --- |
| 위임형 래퍼 | dh-dev 절차 본문을 복제하지 않고 `skills\dh-dev\SKILL.md`를 읽어 그대로 수행 | dh-dev는 계속 개정되는 문서다. 복제하면 곧 어긋난다 |
| 독립 검증 에이전트 | 실행 에이전트와 분리된 별개 에이전트가 증거를 요구하며 완료조건을 항목별로 판정 | 자기 승인 방지. 증거 없는 합격은 오케스트레이터가 기계적으로 강등 |
| 안정 키 기반 정체 판정 | 완료조건 문구가 바뀌어도 안정 키가 같으면 같은 항목으로 보고 연속·누적 불합격을 센다 | 재계획이 완료조건을 슬쩍 바꿔 정체 감지를 피하는 것을 막음 |
| 전용 브랜치 격리 | 회차 커밋은 `dh-loop/<slug>` 브랜치에서만. `main`·`master`에서는 금지 | 무인 루프가 실패 회차 커밋을 주 브랜치에 쌓는 것을 막음. 이 저장소의 `autoresearch` 선례를 따름 |
| 저장소 안 회차 기록 | 회차 상태를 `docs\dh-loop\`의 마크다운 파일에 남김 | 대화가 압축되어도 재개 가능해야 함. 세션 기억은 사라진다 |

### `skills/dh-loop/SKILL.md` (Added)

12개 절로 구성. dh-dev 절차 본문은 한 줄도 옮겨 적지 않고 규칙 이름으로만 가리킨다.

- **위임 계약** — 루프 시작 시 dh-dev 문서를 처음부터 끝까지 읽는다. 규칙을 언급하는 모든 줄에 `dh-dev`를 함께 적어 복제와 구분한다
- **루프 상수** — 값이 있는 곳은 이 표 한 곳뿐. 11개 상수(문서 경로, 기록 폴더, 회차 상한, 정체 한도 둘, 검증 모델·강도·재시도, 범위 감시, 브랜치 앞머리, 보호 브랜치)
- **루프 재정의** — dh-dev와 revision-tracker 규칙 중 무인 루프와 충돌하는 6건(OV-1~OV-6)만 덮어쓴다. 각 행에 안전장치를 붙였고, 재정의는 회차 기록 파일 상태가 `Running`인 동안에만 효력을 갖는다
- **단계 계약** — 7개 단계의 입력·출력·실패 처리. `Load`를 뺀 모든 단계는 시작 전 기록 파일 상태를 다시 읽는다
- **회차 기록 파일** — 형식 예시와 규칙 5개. 1회차 맥락을 보존해 대화 압축 뒤에도 재계획 입력 계약을 갖출 수 있게 했다
- **독립 검증 에이전트** — 모델·스폰 방식·격리·입력·금지·출력 형식. 증거 없는 합격은 `no-evidence`로 강등한다
- **정체 판정** — 안정 키로 같은 항목을 식별하고, 실패 요지를 정규화해 개선 여부를 판단한다. 연속 2회와 누적 4회 두 정지 조건. 정지 뒤 사용자 선택 세 가지의 계수 처리까지 규정
- **재계획 입력** — 10개 항목. 앞 두 개는 dh-dev 계획 에이전트의 입력 계약을 무인 회차에서도 채우기 위한 것
- **커밋·브랜치 정책** — 전용 브랜치 생성·전환, 보호 브랜치 금지, 회차마다 커밋, 실패 회차 되돌리지 않음
- **중단과 재개** — 기록 파일 0개·1개·2개 이상 처리, 단계별 재개 지점 4행
- **예외** — 13개 상황별 처리
- **용어 정리** — 9개 용어, 가나다순
